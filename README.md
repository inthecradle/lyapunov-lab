# LYAPUNOV LAB

日本語 | [English](README.en.md)

[**ブラウザで試す**](https://inthecradle.github.io/lyapunov-lab/) · [GitHubリポジトリ](https://github.com/inthecradle/lyapunov-lab)

数式・状態空間・時間グラフを同期して操作する教育用Webアプリです。React + TypeScript + Vite + SVG + KaTeX。3D地形は計算した曲面をSVGへ投影して描き、WebGLや追加ライブラリは不要です。計算はブラウザ内で完結し、APIやデータベースは使用しません。

## 起動

Node.js 24 LTSを推奨します（最低22.12）。リポジトリのルートで実行します。

```sh
npm ci
npm run dev
```

ターミナルに表示されるローカルURLを開きます。通常は `http://127.0.0.1:5173/` です。

## 実装範囲

定理1に関わる比較評価・収束・前方不変性を、具体的なモデルで学べます。

- 周辺を平面にした格子状の3D地形と中央のくぼみ・TCZ境界・状態点・軌跡と視点操作（Vの表示高さを圧縮）
- 3D地形／2D等高線の切り替え（時間・パラメータを維持）
- 2D表示での等高線・TCZ・ベクトル場
- 点のドラッグ／矢印キー移動、初期位置・閾値・地形・減少率・回転率の変更
- 再生／一時停止／リセット／時間スライダーとグラフの同期
- 符号付き残差、正部分ゲージ、接線、指数上限、V/y表示切り替え
- 数式トークンと図の双方向ハイライト、左右ボタンで確認する6段階の証明
- 標準表示は有限時間でTCZへ到達し、進入時の速度を引き継いで内部を漂遊
- TCZ内の過去軌道・現在速度の矢印・グラフ上の到達時刻の表示
- 直感／数式／証明の表示モード、理解確認問題
- モバイル表示、キーボード操作、動きの自動再生なし

メニューは「比較評価」「条件を壊す」「前方不変性」の3つです。条件を壊す実験（弱い減少・周回・外向き）と、境界方向・前方不変性の実験を含み、テーマごとに証明ステップと保証表示も切り替わります。LaSalleは図示メニューから外しています。内部の参考モデルと数値テストは保持しています。

標準の「TCZに入って漂う」は、外側でV̇ = −βVとする到達例と、内部の漂遊モデルをつないだ教材用の軌道です。内部ではVが増減してもθ以下を保ちます。位置と速度は連続ですが、内部軌道は原論文の数式から導出したものではなく、進行方向を引き継ぐ滑らかな楕円軌道を追加しています。「上限と一致させる」では、従来の境界に漸近する比較例も確認できます。

画面上部から定理1・2・3を切り替えられます。定理1の数式モデルと、その成立条件・出典は [docs/mathematics.md](docs/mathematics.md) を参照してください。

### 定理2・3の共有モデル

- 3主体の共有表象を2D平面／3D地形で表示し、初期位置をドラッグ・矢印キー・数値入力で変更
- 全主体は個人評価V_i=0の領域から開始（個人状態r=[0.8, −0.6, 0.5]）。共有表象の初期位置は異なり、個人の快適さと主体間の不整合を区別して確認できます
- 定理2の3Dは、最初から固定された不一致費用Qの地形を表示。個人評価V_iを含まず、個人の谷との深さ比較には使いません。等結合では社会的費用の厳密な分解、不均一結合では下界を表示します
- 定理3の3Dは、同じ平面上の3つの個人の谷（概念図）から開始。「再生」で4秒かけて共通の谷へ変形し、完了後に収束を開始します。通常画面では抽象ポテンシャルA_i、ポップアップでは重み付きのηA_iを表示し、いずれもη>0での谷底はLUBです。谷の中心・幅・深さの変化は説明用で、評価関数や力は変更しません
- 3主体と軌跡を表示。分断時の定理2は結合成分の谷を残し、孤立主体は基準面へ配置
- 表示切り替え・視点の回転は状態と時間を維持し、位置編集はWとLUBも更新
- 定理2では最初からQ≤θの範囲を緑色で表示。定理3の導入後はηAᵢ≤θ_Aの範囲をモデル時刻0から表示。定理3の導入中の緑は谷底の目印でθ判定と区別
- 定理3の変形中はモデル時刻を0に保ち、主体の座標・評価値を維持。一時停止後は途中から再開し、「導入をスキップ」で収束へ進めます。「変形を最初から再生」はモデル時刻を0に戻してやり直します。通常画面の専用スライダーでは任意の途中の形を確認できます。動きを減らすOS設定でも、明示的に再生した導入は自動スキップしません。定理2にモーフィングはありません
- 定理2・3の収束は0.1倍速で再生。グラフの横軸と主な時間表示は収束の再生秒数に統一し、定理3の導入4秒の経過とモデル時間を別表示
- モバイル（幅760px以下）では元のグラフ上で再生し、PCでは3Dのポップアップを開きます。再生中にモバイル幅へ切り替えても、モデル時刻と再生状態を引き継ぎます。3D表示では変形の進捗も維持し、2D表示では導入をスキップして収束を続けます
- ポップアップでも定理3の変形を一時停止・再開・スキップ・再再生できます。閉じる／Escapeで一時停止し、開き直すと途中から再開します。再生が最後まで進んだ後の「再生」は、時刻0からやり直します（定理3の3Dでは導入も再生）
- ポップアップの3Dは通常画面と共通の格子・配色・表示圧縮を使用。収束中の地形と高さの変換は固定し、回転・仰角は操作できます。初期位置の輪郭と現在位置を比較し、地形上の閾値以下の範囲と、集団全体の合成評価の判定を分けて表示します。定理3のη=0では、ポップアップのηA_iの地形は平らになります
- ポップアップの「高さの比較」は評価値0からの固定した線形目盛りを使用。定理2は各主体のC_i=V_i+Σ_jγ_ijS_ijの初期値・現在値を積み上げ表示し、3主体の合計がℒになります。定理3はηAᵢの初期値・現在値・下降量と閾値を表示します
- 定理2・3で座標枠と視点を共有し、集団の重心と軌跡を黄色で表示（定理2は重心保存、定理3はη>0でLUBへ接近）
- 個別の安定、共有への収束、結合の分断を比較
- 原典の組ごとの結合係数γ₁₂・γ₁₃・γ₂₃を操作し、個人評価V_i・不一致・合成評価ℒ／ℒ_Aを表示
- T2はγを変えても3Dの高さの基準と費用グラフの縦軸を揃え、費用・傾斜・収束速度の違いを比較できます。一部の辺だけを強くすると下界Qが変わらない場合があるため、実際の費用は積み上げ図と時間グラフで確認します
- 定理3では抽象化項の重みを変更し、LUBまでの残差を追加表示
- 定理3の安定領域の閾値θ_Aは初期値0.03、操作範囲0〜0.3。定理2のθ（初期値0.1、範囲0〜1）とは別に保持します
- 同じ初期状態・結合設定を保ったまま定理2と3を切り替え、時間を0に戻して比較
- 残差の指数減少、全員の一致、LUBへの収束について、それぞれの保証を表示

共有するのは状態の一部である表象です。個人の状態は別の変数で保持します。結合が分断されると結合内の不一致が減っても全員の一致は保証されません。全員に同じLUBへの項を与える場合は、分断されていてもそのLUBへ収束します。

原典の評価式と、その数値化に採用する具体関数・決定論的な勾配流を画面上で区別しています。二重和Σijは対称な組を往復とも数え、閾値θ／θ_Aへの収束と評価ゼロへの収束を区別します。認知の実測モデルや、原典の最適制御問題の求解ではありません。式・解析解・保証の適用条件は [定理2・3の数学モデル](docs/collective-mathematics.md) を参照してください。3D抽象階層表示と確率的な不確実性のモデルは含みません。

## 検証

```sh
npm test
npm run build
npx playwright install chromium
npm run test:e2e
npm run format:check
```

数値テストでは比較評価・場と解析解の整合性・不変性などを確認します。E2Eテストはデスクトップとモバイルで同期、数式と図の選択、内部初期条件、再生／一時停止、証明ステップの前後移動、条件破壊時の保証表示、TCZへの到達と内部の漂遊を確認します。E2Eは事前に生成した `dist` を使用します。

定理2・3では、地形の変形から収束への移行、一時停止・再開・スキップ・再再生、再生終了後のやり直し、ポップアップを閉じて開き直す操作、PCからモバイルの2D／3D表示への移行を検証します。共通地形格子のテストでは、共有頂点の再利用、変形終点の幾何学的な連続性、描画順、有限な座標・配色も確認します。`format:check` はソースコードなどのPrettierチェックです。

```text
src/components/CollectiveStateSpace2D.tsx         共有表象の平面図と初期位置の編集

src/App.tsx                                       再生・学習ステップの統合
```

定理1の型と描画は単一主体用のまま保持し、定理2・3のモデルと描画を分離しています。数式と図の選択・再生・シークは同じ操作体系で使えます。定理2・3の解析解は任意の時刻で再評価するため、逆シークによる積分誤差の累積はありません。

通常画面とポップアップの地形格子・配色は `collectiveTerrainMesh.ts` に集約しています。40×40枚の面が共有する41×41個の頂点を一度ずつ評価・投影し、頂点の計算を6,400回から1,681回に削減しています。`CollectiveTerrainSurface.tsx` は描画結果をメモ化し、収束中の主体や軌跡の更新に伴う固定地形の描画処理を抑えます。これらは表示専用で、モデルの費用・力・解析解は変更しません。

導入と収束の別々の時計、アニメーションの停止、2D／3D表示と画面幅に応じた再生処理は `useCollectivePlayback.ts` にまとめています。モバイル2Dでは、表示されない導入アニメーションを待たずに再生を進めます。

## 共通のシリーズ表示

ヘッダーとフッターは `src/components/SeriesChrome.tsx` と `series-chrome.css` に分離しています。`SeriesChrome.tsx` はReact製のLYAPUNOV LAB / EVOLUTION LAB / INVERSE LIMIT LABの3作品で、`series-chrome.css` は静的HTMLのHJB LABを含む4作品で同じ内容を保持します。各アプリを独立してビルドでき、共通デザインを変更するときは該当する全コピーを同期します。
